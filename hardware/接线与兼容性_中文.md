# MutaScape 硬件接线与兼容性

根据你提供的程序整理；未在你的物理板上测试。网页中的 LED、交通灯与舵机图是浏览器教学演示。

## 上传程序的差异

| 文件 | 环境 | 输入 | 已支持的主要输出 |
|---|---|---|---|
| microbit_makecode.py | MakeCode Python | P0 旋钮、P2 声音输入、内置 A/B；P1 可选 A；P8/P12 红外映射 B | SEV:0–100；小写 danger/moderate/stable；P14/15/16 交通灯（active-low） |
| microbit_muta_controller.py | MicroPython | P0/P2、内置 A/B、P1/P8/P12 诊断 | SEV；SOUND:DANGER/MODERATE/STABLE；P13 NeoPixel、P14/15/16 交通灯（active-high） |
| microbit_mutascape.py | MicroPython | P0/P2、P1/P3 外接按钮及红外；与内置按钮版本不同 | SEV、WARN、部分模式/视图及声音指令 |
| microbit_test.py | 电脑上的 Python | COM3 / 115200 串口读取 | 无 |

文件原样保存在 `original-code`。MakeCode Python 与 MicroPython 不可互换粘贴。

## 浏览器怎么连接

1. 确认实际烧录的是哪个程序；先用对应编辑器检查程序适合 micro:bit 型号。
2. 使用 Chrome / Edge，在 HTTPS 页面或 localhost 中打开网站，插上 micro:bit 的 USB 数据线。
3. Pressure board → Connect board → 选择设备；连接速率 115200。
4. 选择 firmware profile；Use live inputs 开启后才把串口输入用于网页。
5. 点 Send LED / traffic index 才发送输出；不会在你移动网页滑块时自动发送。
6. MakeCode profile 只发 `SEV:n`，可选小写声音指令；controller profile 发 `SEV:n` 与可选 `SOUND:...`。Read only 不发任何命令。

连接失败或没有板子也能操作全部浏览器演示。

## 可解析的输入

- `POT:700 MIC:512`，也支持 `DBG:P0=700 P2=512`。
- `A` / `B`；MakeCode 连续发送的锁存 A/B 以一段消息视为一次，停止超过 500 ms 再接受下一段。
- `EVT:A SEQ:1`；相同序列事件只执行一次，建议今后 firmware 用这种明确事件格式。
- `CONTACT:1` / `CONTACT:0` 可控制网页的接触演示。

P1 原始电平在不同程序里解释不一致，网页不自动将它当作接触状态。上传的 MakeCode 程序并不发送 CONTACT，因此该 profile 下接触开关可以手动控制。声音输入只转成教学环境强度，不等于细胞实验里的应激量。

## 舵机仍待确认

现有程序没有一致实现 Streamlit 发出的 `SERVO:` / `RGB:` / `TL:` 命令。网站不会发送它们，也不会自动运行 SERVOSCAN。网页舵机 WT 0° / Mutant 180° 只表示教学状态。

要做真实舵机连接，需要你补：

- micro:bit V1 或 V2；
- 扩展板准确名称/型号；
- 舵机信号线对应的针脚；
- 舵机供电方式；
- 正在烧录的完整程序。

确认后才能写适合该板子的舵机代码，而不是猜针脚。交通灯 active-low / active-high 也必须与实际板子一致。
